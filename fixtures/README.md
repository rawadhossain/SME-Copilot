# Fixtures (SYNTHETIC)

Everything here is invented. No real company, person, bank or customer. Names carry a "(SYNTHETIC)" suffix.

| File | What it is |
|---|---|
| `bank-statement.csv` | Bank export for the synthetic business, generated by `bun run db:seed` from the same transactions stored in the database. Layout: `Date,Description,Amount,Balance` (ISO dates, signed amounts, running balance). Importable with `bun run import:csv`. |
| `purchase-order-northgate.md` | A GBP 180,000 purchase order from the grocery chain on 60-day terms. **Not processed yet**; for the later document-extraction work. |
| `supplier-quote-kestrel.md` | A supplier quote needing a 30% deposit now and the balance on shipment in week 5. **Not processed yet.** |

| `injected-purchase-order.md` | The same purchase order with instructions aimed at an AI reader added. **Synthetic security test fixture**, written by the seed (or `bun scripts/make-injected-fixture.ts`). |
| `llm-recordings/` | **Scripted** (not real model) responses for the three documents, so the document reader works offline in replay mode. Regenerate with `bun run llm:record-scripted` if the fixtures change. |

The purchase order and the supplier quote do not change with the seed parameters. The files are deterministic: the same "as of" date gives the same content. Dates are relative to the fixed demo date 2026-10-15 (`DEFAULT_DEMO_AS_OF`), not the day the seed is run, so the recorded model answers replay on any day (override with `SEED_AS_OF=YYYY-MM-DD`, which needs new recordings). Regenerate with `bun run db:reset-seed`.
